# Подтверждение email при регистрации

## Суть
После регистрации пользователь получает письмо с кнопкой "Подтвердить". Неподтверждённые аккаунты не могут войти.

## Бэкенд

### 1. Модель User — `backend/models.py`
Добавить 2 колонки:
```python
email_verified = Column(Boolean, default=False, nullable=False)
verification_token = Column(String(64), nullable=True)
```

### 2. Миграция — `backend/main.py:52-66`
Добавить в блок ALTER TABLE:
```python
conn.execute(text("ALTER TABLE users ADD COLUMN IF NOT EXISTS email_verified BOOLEAN DEFAULT TRUE"))
conn.execute(text("ALTER TABLE users ADD COLUMN IF NOT EXISTS verification_token VARCHAR(64)"))
```
Существующие пользователи получат `email_verified=TRUE` (уже активны).

### 3. Схемы — `backend/schemas.py`
- Добавить `VerifyEmailRequest(BaseModel): token: str`
- Добавить `email_verified: bool = True` в `UserResponse`

### 4. `send_gmail` — `backend/main.py:19-47`
Добавить параметр `content_type: str = "plain"`, заменить `"plain"` → `content_type` в MIMEText.

### 5. Регистрация — `backend/main.py:93-106`
- Генерировать `secrets.token_urlsafe(32)` как verification_token
- Создавать пользователя с `email_verified=False`
- Отправлять HTML-письмо с кнопкой "Подтвердить email"
- Ссылка: `https://praktika2-eta.vercel.app/verify-email?token=xxx`
- Тело письма — HTML с styled кнопкой (как в админ 2FA, но HTML)

### 6. Верификация — новый эндпоинт `POST /api/verify-email`
- Принимает `{ token }`
- Ищет пользователя по `verification_token`
- Проверяет токен (не None) — если нет, 400
- Ставит `email_verified=True`, `verification_token=None`
- Возвращает `{"message": "Email подтверждён"}`

### 7. Логин — `backend/main.py:108-150`
После проверки пароля (строка 112), перед проверкой is_admin (строка 115):
```python
if not db_user.email_verified:
    raise HTTPException(status_code=403, detail="Подтвердите ваш email перед входом")
```

## Проверка
1. Зарегистрировать нового пользователя → появляется "Проверьте почту"
2. Проверить почту → письмо с кнопкой "Подтвердить"
3. Нажать кнопку → редирект на /verify-email?token=... → "Email подтверждён"
4. Попробовать войти до подтверждения → ошибка 403
5. Войти после подтверждения → успешный вход
6. Существующие пользователи — вход без проблем (email_verified=TRUE по умолчанию)
